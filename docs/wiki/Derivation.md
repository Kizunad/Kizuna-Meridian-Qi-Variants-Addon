# 合成与权重规则

协议为 [qi_variants.proto](../../shared/src/main/proto/kizuna/meridian/qi_variants/v1/qi_variants.proto)。`VariantCatalog.schema_version = 1`，包含属性元数据与合成配方；替换开发期旧单父树模型，不提供旧目录兼容读取。

正式内容唯一编辑入口为 [qi-variants.textproto](../../server/src/main/resources/qi-variants.textproto)。修改它即可更新导出的目录与框架属性登记包，不需要修改 Java。

| 产物 | 输入比例 | 损耗率 | 自动阶数 |
|---|---|---|---|
| 枯 `qi_variants:withering` | 金 : 木 = 1 : 1 | 35% | 1 |
| 凋零 `qi_variants:wither` | 枯 : 火 = 1 : 1 | 45% | 2 |

展示名称和 RGB 颜色暂为占位内容。五行根是 `meridian:metal / wood / water / fire / earth`，阶数为 0。`meridian:none` 不参与合成，也不接受为区域权重输入。

## 目录校验

属性 ID 必须符合框架内容 ID 格式、互不重复，不能使用框架保留的 `meridian` 命名空间。展示名非空，`color_rgb` 必须显式提供且在 `0x000000..0xFFFFFF`；黑色 0 合法。公开加载入口还检查每个属性已在框架注册为 `QI_ATTRIBUTE`。

每条合成配方有唯一 ID 和正整数版本；同一产物可以有多条配方，但目录内相同 ID 的不同版本也不能并存。输入至少两种不同属性，只能引用五行或当前目录的变体；比例正且有限。产物必须是当前目录变体。`loss_ratio` 必须显式提供、有限且位于 `[0,1)`。最低境界可缺省；显式提供时只接受框架已知的非零枚举。

每个变体至少有一条配方；全部配方边组成的图必须无环。有另一条可行路线时，循环路线仍会导致整份目录拒绝。任意校验失败都不交付部分目录，也不修改框架注册表。

## 阶数与祖先

单条路线的阶数是 `max(各输入属性阶数) + 1`；同一产物取所有路线的最低值。不手填阶数，也不人为设置上限。

阶数和权重均按完整合成图的拓扑顺序计算，不能按最小阶数排序：某低阶产物的另一条路线可能引用更高阶的原料。

`ancestors(id)` 返回所有路线的传递输入并集，包含五行、不含自身，按 ID 排序且不可变；五行的祖先集合为空。它不是单一父链。`tier`、`recipesFor`、`ancestors` 查询未知属性时明确拒绝。

## 区域权重

`weights(regionShares, maxTier)` 接收五行和当前目录变体的数量或相对份额 Map。缺项视为 0；所有值必须有限非负，未知属性、空值和无属性真元拒绝。`maxTier` 必须非负。

先将区域输入归一化为直接份额，再按拓扑顺序计算：

```text
weight(五行 e) = directShare(e)
weight(变体 v) = max(directShare(v),
                    max_over_recipes(product(weight(每种输入属性))))
```

计算完整图后，保留 `tier <= maxTier` 的正权重属性，再归一化为概率。阈值只筛最终候选，高阶属性仍可经另一条路线影响低阶候选。零区域或筛选后没有正权重时返回空 Map，抽取返回 `Optional.empty()`。

例如金、木各占一半，一阶产物原始权重为 `0.5 × 0.5 = 0.25`，最终金、木、产物概率为 `0.4 / 0.4 / 0.2`。区域直接存在的变体也能参与后续合成权重。

配方比例与损耗不参与出生权重，因此 `1:1` 与 `1:99` 在相同输入种类下的权重相同。这是出现倾向，不是实际合成产量。首版不提供每阶缩放配置，等效于全部为 1。Threatening 可用 `maxTier = 1` 表示游炁候选、`maxTier = 2` 表示真炁候选，境界不在本库权重查询中隐式推断。

结果不可变且按 ID 稳定排序；随机源由调用方提供。归一化先缩放避免有限大数求和溢出，极小权重仍可能受 `double` 精度限制下溢为零。

## 器官配方转换

转换工具由调用方指定目标配方 ID、版本、器官种类、输入总量 `batchQi`、正整数加工毫秒和密度：

```text
输入 i = batchQi × ratio_i / sum(ratios)
产物 = 实际输入总量 × (1 − lossRatio)
```

批量必须正且有限，密度满足框架有限且不小于 0.01 的规则。输入比例先缩放后求和；实际合计可能有浮点尾差，产物按实际可表示的输入合计计算，确保零损耗不会制造真元。输入、产物或损耗无法用 double 有效表示时拒绝转换。

所有输入要求和产物使用调用方指定的同一密度，因此不跨相态。框架实际取料按属性及相态区间匹配，保留原料真实密度；转换工具不承诺产物动态继承实际输入的精确密度。

损耗完全遵循框架规则：完成时转成 `meridian:none`、密度 0.01 释放环境。例如 1 元金和 1 元木生成 1.3 元枯，0.7 元作为无属性游离真元释放。损耗不作为器官缓存输出，也不按原输入属性退回。

最低境界缺省映射到 `WANDERING_QI`，表示没有额外门槛。转换结果是框架 `BodyMessages.OrganRecipe`，可直接通过框架校验；工具不自动安装或执行配方。
